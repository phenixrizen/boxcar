> Process note: the current repository contract and [review policy](../review-policy.md)
> supersede this plan's historical instructions about planning, review counts,
> task splitting, parallel work and check selection. Technical requirements,
> acceptance criteria and recorded results below remain relevant. Run the suites
> for affected surfaces; an unavailable or skipped KVM run is never a pass.

**Goal:** After M5, `boxcar run --image docker.io/library/alpine:3.22 --policy agent-isolate -- sh -c 'apk add curl'` pulls the image unprivileged, verifies every blob by digest, boots the guest from a per-session copy of the image's root filesystem, enforces a TOML policy (egress, writable and denied paths, a denied-program list) at ring 0 with live, expiring exceptions, and runs with its VMM process confined by seccomp and Landlock. `boxcar audit export SESSION --format otlp` turns the session into one OpenTelemetry trace (the session, each model call, each tool span with its findings as span events), and `--format ocsf` into OCSF 1.x events, both deterministic. The docs cover the architecture, the boot, images, policy, export and WSL2, and a tag builds a release.

The design this plan argues from is `docs/specs/2026-09-29-boxcar-design.md` (milestone 5 in its section 12, amended in section 14). The roadmap's M5 rows (`docs/plans/2026-09-30-boxcar-roadmap.md`, M5.1 to M5.5, and its "Policy (`boxcar-policy`, M5)" section) are superseded by this plan where they differ; the differences are argued in section 3 and recorded in section 8.

- Environment and builds as in the M4 plan's section 2: Rust 1.96.0, `CARGO_INCREMENTAL=0`, guest artifacts in `target/guest`, `cargo xtask initramfs` after any init or sensor change, never copy the tree or `git clean`.
- For affected runtime work, the applicable checks are: `cargo test --workspace`; `cargo clippy --workspace --all-targets --features boxcar-vmm/kvm-tests,boxcar/kvm-tests -- -D warnings`; `cargo fmt --all --check`; `cargo deny check`; `cargo xtask schema` leaving no diff under `proto/`; `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps`; `cargo xtask sensor` and `cargo xtask check-vmlinux` when the sensor crates change; `cargo xtask test-kvm m3` and `m4` when the VMM, the net stack, the filesystem, init, the sensor, the audit crate or the CLI change, and `m5` from Task 3 on. - Tests first: each test fails for the right reason before the code exists. No `unwrap`, `expect` or `panic!` outside tests. Nothing logs on a vCPU thread or on the stop path. A guest never blocks the VMM, ring 1 never blocks ring 0, the gate never modifies a byte it relays, and no credential value (registry credentials included) reaches a record, a dump, a log line, a fixture or test output.
- Every new file carries `// SPDX-License-Identifier: Apache-2.0` and `// Copyright 2026 The boxcar Authors` (the eBPF crate's sources `MIT OR GPL-2.0`).
- Commits: `git commit -s`, one logical change each, subjects from this plan verbatim, body ending with `Co-Authored-By:` naming the executing session's model, `Claude-Session: <the session's URL>`, then the sign-off. Never commit `target/`. GitHub's push protection refuses credential-shaped literals (a Stripe test key in a unit test was refused in M4): build fake credentials at run time.
- Every judgment call goes into the commit message or section 8, appended as work proceeds by the task's pull request. Deferred findings are reported at the end, explicitly.
- Current shipping, planning and review rules are in `AGENTS.md` and `docs/review-policy.md`. Use existing task issues, keep one coherent outcome with its necessary corrections/tests, and split independently useful, risky or revertible work. ## 3. Binding technical constraints

- **Dependencies.** Workspace additions, crates.io only, no git dependencies, no `[patch]`: `ureq = { version = "3.4", default-features = false, features = ["rustls-no-provider"] }` with the `ring` provider and roots from `rustls-native-certs` (the gate's store), `tar = { version = "0.4", default-features = false }`, `ruzstd = "0.9"`, `toml = "1"` (`serde` support only), `globset = "0.4"`, `seccompiler = "0.5"`, `landlock = "0.4"`. SHA-256 comes from `ring::digest` (already in the tree), gzip from `flate2`. No `tokio`, `reqwest`, `hyper`, `oci-client`, `ocirender`, `prost` or `opentelemetry*`. Any duplicate version these bring is resolved by matching versions, not by a `skip`, unless the decision says why; `deny.toml` gains a licence only by a recorded decision. `ureq` 3.4 needs `base64` 0.23 where the workspace has 0.22, used only by boxcar's own crates (`boxcar-fs`, `boxcar-net`, `boxcar-proto`): Task 2 moves the workspace to 0.23.
- **Crate boundaries.** `boxcar-policy` depends on `boxcar-net` (the line policy) and `boxcar-fs` (the path rules); neither depends on it. It compiles a policy into the views each crate already reads: a `boxcar_net::Policy` plus the DNS rate for the net stack (its `ArcSwap` as today) and a `boxcar_fs::PathRules` (writable, denied and exec glob sets) for every `AuditFs`. The VMM holds the policy and swaps both views on a change.
- **The image store.** `$XDG_CACHE_HOME/boxcar` (else `$HOME/.cache/boxcar`), mode 0700: `blobs/sha256/<hex>` (each blob written to a `.partial` file, its SHA-256 checked against the digest, then renamed; a mismatch deletes it and fails the pull), `images/<manifest-hex>/{rootfs,image.json,refs}`, and `refs/<registry>/<repository>/<tag>` naming a manifest digest. A cache entry is whole or absent (built in `<name>.partial` and renamed). `boxcar image pull REF`, `boxcar image ls`, `boxcar image rm DIGEST|REF`, `boxcar image prune`.
- **The registry client** (`crates/boxcar/src/oci/{reference,client,manifest,unpack,store}.rs`): references as Docker parses them (`alpine` → `docker.io/library/alpine:latest`, `@sha256:` digests, ports); the distribution API's `GET /v2/<name>/manifests/<ref>` with the OCI and Docker v2 media types accepted, an image index resolved to `linux/amd64`, then the config and layers by digest; anonymous bearer tokens from the `WWW-Authenticate` challenge; credentials only from `~/.docker/config.json` `auths` (base64 `user:password`; credential helpers are refused with a message), never recorded or logged, absent from errors. HTTPS only, except `127.0.0.1` for a `kvm-tests` build's test registry. Limits: manifest 4 MiB, config 1 MiB, 128 layers, each blob's size as the manifest says and at most 8 GiB, a 30 s timeout per request without progress. Layer media types: `tar`, `tar+gzip`, `tar+zstd` (OCI and Docker names); anything else fails the pull.
- **Unpacking.** Layers are applied in order into one tree, `images/<manifest-hex>/rootfs.partial`, as an unprivileged user: every path is created with `openat2(dirfd, RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS)` from the tree's directory fd (as `hasher.rs` opens files), so no entry, symlink or hardlink of any layer can reach outside it. `.wh.<name>` removes `<name>` from the layers below; `.wh..wh..opq` empties its directory of what the layers below put there. Regular files, directories, symlinks and hardlinks (within the tree) are made; mode bits are kept, setuid and setgid included where the host allows them; ownership is not (everything belongs to the invoking user); character and block devices and FIFOs are skipped and listed in `image.json` (`skipped`). The tree's root must hold `/tmp` (1777) and `/workspace`. Decompression is bounded as it streams, since a layer that passes its digest and size checks can still expand without limit: at most 16 GiB of decompressed stream per image (all layers together, tar headers and skipped data included, counted as the decompressor yields it) and 1,000,000 entries; past either the pull fails and `rootfs.partial` is removed. `tar` reads GNU long-name and long-link records and PAX headers whole into memory before it yields an entry, and its raw entries (`Entries::raw(true)`) ignore a PAX `size` when framing the next one, so Task 2 frames the stream itself. Each 512-byte header is parsed with `tar::Header`, its checksum checked, and entries are dispatched by kind:
  - PAX local headers (`x`) are read into a buffer of at most 64 KiB and parsed with `tar::PaxExtensions`.
  - GNU long names and long links (`L`, `K`) are read into a buffer of at most 64 KiB and taken as a raw NUL-terminated name.
  - PAX global headers (`g`) are read within the same cap; they fail the pull when they set `size`, `path` or `linkpath`, and are otherwise ignored.
  - Larger extension records fail the pull.
  - The overrides gathered (`size`, `path`, `linkpath`, through any run of extension headers: `x`, then `L`, then the file) apply to the next ordinary entry before its data and padding to 512 bytes are read.
  - Sparse files are refused in M5: a GNU sparse entry (`S`), or any `GNU.sparse.*` PAX key, fails the pull.
  - Two zero blocks, or one zero block followed by the end of the stream, end the archive.

  Task 2's own plan carries this contract. Its tests include:
  - a highly compressible layer;
  - oversized PAX and GNU extension records;
  - a valid layer whose PAX `size` differs from its header's;
  - valid `L` and `K` long names, and an `x`, `L`, file run;
  - both sparse encodings, refused;
  - a bad checksum.
- **Running from an image.** `boxcar run --image REF` (conflicts with `--rootfs`; `--pull missing|always|never`, default `missing`) copies `images/<manifest-hex>/rootfs` into the session directory as `rootfs` (`FICLONE` reflinks where the filesystem has them, a plain copy otherwise; hardlinks are never shared with the cache) and serves that copy as the root share, so the cache is never written through a session. Before the guest boots, the host makes in that copy every path init creates on the root share at boot (its mount points and `/etc/resolv.conf`, which the Alpine minirootfs lacks), so a policy that refuses writes there never stands between init and its setup; Task 3's plan lists them from `boxcar-init`, and Task 5 boots `agent-isolate-strict` from an image without `/etc/resolv.conf` and reaches an allowed host by name. The image's config supplies the defaults: `Entrypoint` + `Cmd` when `boxcar run` is given no command, `Env` (before the session's `--env`), `WorkingDir`; `User` is ignored (the session runs as the host user, as today; decision). `vmm.start` gains `image: Option<ImageRef{reference, manifest_digest, config_digest}>` (omitted when there is none). Not OverlayFs: its `rename` is `EXDEV` (section 1); a per-session copy keeps every POSIX operation and `AuditFs<PassthroughFs>` as it is. A lower-and-upper overlay of our own is a later milestone's, recorded as a decision.
- **Policy files.** New crate `crates/boxcar-policy` (`model`, `parse`, `eval`, `profiles`, `live`). TOML, `deny_unknown_fields`, `version = 1` required:
  - `[egress] default = "allow"|"deny"`, `allow`, `deny`, `inspect` (arrays of today's target strings, compiled through `boxcar_net::Policy::parse` so the semantics are exactly the line policy's), `max_dns_qps` (optional; a query over the rate is answered `REFUSED` and recorded `net.dns{verdict:"deny", rule:"dns_rate"}`).
  - `[fs] writable` (guest-path globs; a mutating operation on a share path matching none of them is refused `EROFS`), `denied` (globs; `lookup`, `open`, `create` and every mutating operation refused `EACCES`), `indicators` (globs added to the reconciler's `indicator_removal` paths). `/workspace/**` and `/tmp/**` are writable unless `writable` is given (`/tmp/**` added by Task 5, section 8). Paths are matched as the guest names them (the share's `guest_path` joined to the share-relative path), with `globset` (`literal_separator = true`).
  - What a path is, at ring 0. A request that carries a name (`lookup`, `create`, `mkdir`, `mknod`, `symlink`, `link`, `rename`, `unlink`, `rmdir`) is checked by the path it names. A request that carries only an inode (`open`, `setattr`, `write`, `setxattr`, ...) is checked by every name the share's `PathMap` knows for that inode, its hardlinks included: it is refused when any of them is denied, and allowed to write only when all of them are writable. A symlink is resolved by the guest before the request reaches the host, so a rule applies to the file a link leads to, not to the link's name. `PathMap` follows renames as it does today; Task 5's plan sets out the orderings (a rename racing a check, a link made after a lookup) and the tests that pin them.
  - `[exec] deny` (guest-path globs): opening a share file for exec (`__FMODE_EXEC`) whose names match is refused `EACCES`. It denies program files, not the names they are run by: a BusyBox applet (`/usr/bin/nc` linking to `/bin/busybox`) is BusyBox, so `**/nc` stops a real `nc` binary but not the applet, and the docs say so. Ring 0 only in M5; a program copied to the guest's tmpfs first is not on a share and is not stopped (documented; the copy itself is a recorded write, and the reconciler's existing rules still see the exec, by its name).
  - `[spans] keep_tool_args = true|false` (default true: `tool.open.args` inline to 8 KiB as today), `[record] scrub_argv = true|false` (the same as `--scrub-argv`).
  - Refusals are `fs.denied{..., reason: "policy", rule}` (new optional fields), never sampled, and the reconciler's `policy_denial` already scores them.
  - Built-in profiles in `profiles.rs`, selected by name: `agent-isolate` (deny by default; `inspect` and `allow` for `api.anthropic.com`, `*.anthropic.com`, `api.openai.com`, `chatgpt.com`, `*.openai.com`; `allow` for package registries (`registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`, `crates.io`, `static.crates.io`, `index.crates.io`, `dl-cdn.alpinelinux.org`, `deb.debian.org`, `security.debian.org`) and git hosts (`github.com`, `*.githubusercontent.com`, `codeload.github.com`, `gitlab.com`) on 443; `max_dns_qps = 20`; writable `/**`, since the root share is the session's own copy of the image and a package manager writes `/usr`, `/lib`, `/etc`; indicators as the reconciler's today) and `agent-isolate-strict` (the same egress, writable `/workspace/**` and `/tmp/**` only, so a package install fails there, and `[exec] deny` for `**/nc`, `**/ncat`, `**/socat`, `**/telnet`). Each is a TOML text in the binary, printed by `boxcar policy profile NAME`.
  - `boxcar run --policy FILE|NAME` (conflicts with `--policy-file`, which keeps the line format; `--allow`, `--deny`, `--inspect` still add to either). `policy.loaded{source ("file"|"profile"|"flags"), name, sha256 (of the TOML text), egress_rules, fs_rules, exec_rules}` is recorded before the guest boots. The VMM holds the policy and the views compiled from it (crate boundaries, above).
- **Live exceptions.** The permanent policy and the exceptions are held apart; the views are compiled from the permanent policy with the live exceptions added. `policy.update` gains `exception: Option<{rule: String (an egress target, an `fs` glob or an `exec` glob), kind ("egress"|"writable"|"exec"), ttl_s: u32 (1 to 86400)}>`: the exception gets an id, `policy.exception{id, rule, kind, ttl_s, expires_ns, by_pid, version}` is recorded, and at expiry a timer on the VMM's event loop removes that id and records `policy.changed`. `policy.get` answers the permanent policy and the live exceptions separately, and a `policy.update` with `net` or `vsock` replaces only the permanent policy, so a client that read an exception cannot make it permanent by writing back what it read. Two grants of the same rule are two exceptions with their own expiries; a permanent rule the same as an exception stays when the exception expires. Updates and expiries are serialized (under `LivePolicy`'s lock), and an expiry is a policy swap like any other: flows the remaining policy denies are revoked, as the net stack does today. At most 64 live exceptions. Task 5's plan sets out these orderings and their tests. `boxcar policy allow RULE --ttl DURATION` (`10m`, `1h`) and `boxcar policy exception ls`. Hello's capabilities gain `policy.exception`. `KINDS` grows to 59.
- **Export.** `boxcar audit export SESSION_DIR --format otlp|ocsf [--out FILE] [--otlp-endpoint URL]`, reading a verified log (a chain failure stops the export), writing JSON:
  - OTLP: one `ExportTraceServiceRequest` in OTLP/JSON (OTLP 1.x JSON encoding: hex ids, `timeUnixNano` strings, `resourceSpans` → `scopeSpans` → `spans`), POSTed to `<endpoint>/v1/traces` with `Content-Type: application/json` when an endpoint is given. Trace id: the session id's 16 bytes (UUIDv7). The session span (`vmm.start` to `vmm.stop`), a span per `llm.request`/`llm.response` pair (`gen_ai.system`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.response.finish_reasons`), and a span per tool call (`tool.open` to `tool.close`, child of the model call that asked for it, span id the first 8 bytes of BLAKE3 of the `tool_use_id`; attributes `gen_ai.tool.name`, `gen_ai.tool.call.id`, `boxcar.tool.args_b3`, `boxcar.span.procs`, `boxcar.span.effects`, status from `tool.close`) with each finding in it as a span event (`boxcar.finding.category`, `score`, `rule`, `summary`, evidence seqs). Resource attributes `service.name = "boxcar"`, `boxcar.session.id`, the image, the policy's sha256. No record's raw text beyond the summaries the log already holds.
  - OCSF 1.x JSON lines: `fs.*` as File System Activity (1001), `proc.exec`/`proc.exit` as Process Activity (1007), `net.connect`/`net.close` as Network Activity (4001), `net.dns` as DNS Activity (4003), `http.*` as HTTP Activity (4002), `finding` as Detection Finding (2004), `tool.*` and `llm.*` as API Activity (6003); every event carrying the record's `seq` and hash in `metadata` so it points back into the chained log. Unmapped kinds are skipped and counted.
  - Both are deterministic for a given log (no wall clock, stable ordering): blessed snapshots of a fixture session (`BOXCAR_BLESS=1`), byte-for-byte.
  - The control op `audit.verify{from_seq?}` (the roadmap's) answers the writer's chain state.
- **Hardening.** In `crates/boxcar-vmm/src/hardening.rs`, recorded in `vmm.start` as `hardening{seccomp, landlock}` (`"enforce"|"log"|"off"`, `"full"|"partial"|"unsupported"|"off"`):
  - Landlock confines the thread that applies it and the threads it starts later, never threads already running (and the crate's all-threads option needs an ABI newer than the test box's kernel). So it is applied on the main thread before the first thread of the session starts (`audit-writer` and `reconcile` start before `Vmm::new` today), with rules for every path the session will touch, and every later thread inherits it. Best ABI the kernel offers, `CompatLevel::BestEffort`: read and write beneath the shares' host directories, the session directory, the audit directory, the state directory and the dump directory; read beneath the kernel and initramfs paths, the system trust store's files and `/etc/resolv.conf`; `/dev/kvm`; nothing else by path, the list measured by Task 7 (`/proc/self` included if the session reads it). An unsupported kernel records `"unsupported"` and runs on. Task 7's plan orders the setup so no thread starts before it, and a test shows a denied access from a worker thread.
  - seccomp: one allowlist for the whole process, installed with `SECCOMP_FILTER_FLAG_TSYNC` once the VM is built and before the first vCPU runs, so every running thread and every later one has it. Built with `seccompiler` from the syscalls the VMM uses, measured on the test box with `strace -f -c` over `test-kvm m1` to `m5` and kept in `hardening.rs` with a comment per group; arguments filtered only for `ioctl` (KVM, vsock, terminal and FIONREAD requests by number), `socket` (families), `clone` (thread flags only), `prctl` (the options used). `clone3` passes its flags in memory a filter cannot read, so it is answered `ENOSYS`, and the C library falls back to `clone`; a test starts threads after installation. `--seccomp enforce|log|off`, default `enforce`; `log` uses `SECCOMP_RET_LOG` for building the list. Any other disallowed call kills the process (`SECCOMP_RET_KILL_PROCESS`), with no teardown: that is a crash, and a kill between a checkpoint and its index entry, or in the middle of a flush, leaves a log `boxcar audit verify` rejects today. Task 7's plan settles how verify tells a crash's torn tail (a partial last line, a checkpoint without its index entry) from a broken chain, with a test killing at each point; the gated suites prove the list covers every path they reach, the stop and failure paths included.
  - `boxcar doctor` adds: nested virtualization on WSL2 (`/proc/cpuinfo` without `vmx`/`svm` under WSL prints the `.wslconfig` and `wsl --shutdown` hint), Landlock and seccomp availability, and the image cache's free space.
- **Everything M4 fixed stays fixed**: the record kinds and their fields (only the additions above), the gate, the observer and its budgets, spans and their close rule, the sensor's programs, the line policy's semantics, the control limits and error codes, exit codes, `--scrub-argv` and `--dump-payloads`.

## 4. Review focus

1. **A layer that escapes its tree** (a `../` name, an absolute path, a symlink then a file through it, a hardlink to `/etc/passwd`, a whiteout of `..`). Expected: the pull fails or the entry is refused, nothing outside `rootfs.partial` changes. Pinned by Task 2's `layers_never_write_outside_the_tree` (crafted tars) and a proptest over entry sequences.
2. **A blob that is not what its digest says**, or a manifest that lies about sizes. Expected: the pull fails, nothing enters the cache. Pinned by Task 2's `a_blob_that_does_not_match_its_digest_is_refused`.
3. **Registry credentials** in the log, an error message or the test output. Expected: nowhere. Pinned by Task 2's `credentials_never_leave_the_client`.
4. **A session writes through to the image cache.** Expected: impossible; the root share is the session's own copy. Pinned by Task 3's gated `a_session_never_changes_the_cached_image` (hashes the cached tree before and after a session that writes everywhere it can).
5. **A path the policy denies, reached another way**: a symlink into a denied directory, a rename onto a denied path, a hardlink of a denied file made before or after the policy, `..` in a name, a case variant. Expected: refused by every name the share knows for the file, `fs.denied{reason:"policy"}`. Pinned by Task 5's table of attempts against `AuditFs`, and a gated run with a symlinked program and a hardlink.
6. **An exception that outlives its TTL**, one granted beyond the limit, or one made permanent by a client writing back what it read. Expected: removed at expiry with `policy.changed` and its flows revoked, the 65th refused, a whole-policy update never carrying an exception, overlapping grants expiring on their own times. Pinned by Task 5's `an_exception_expires_on_the_loop` (with the manual clock) and its ordering tests.
7. **A syscall the VMM makes only on a rare path** (the stop path, the audit writer's failure path, a vsock reset, the observer's degrade, a thread started late), or **a thread outside Landlock**. Expected: on the allowlist; `clone3` answered `ENOSYS`; every thread confined. Pinned by Task 7's suites under `enforce`, a unit test that every syscall named in the list resolves on x86_64, and a denied access tried from a worker thread.
8. **Exports that are not deterministic** or that carry what the log does not. Expected: byte-identical exports of the same log; no field beyond the records' own. Pinned by Task 6's snapshots and a test that exports a fixture twice.

## 8. Decisions (appended while executing this plan)

Made while writing the plan, 2026-10-13:

- **A per-session copy of the image, not an overlay.** fuse-backend-rs 0.14's `OverlayFs` answers every `rename` with `EXDEV`, and package managers rename into place. A copy of the cached tree per session (reflinked where the filesystem can) keeps every operation and `AuditFs<PassthroughFs>` unchanged, costs a copy per session on filesystems without reflinks, and makes "a session never writes the cache" structural. An overlay of our own (lower read-only, upper per session, copy-up with times and xattrs, `rename` within the upper) is a later milestone's.
- **Our own registry client on `ureq`, not `oci-client` and `ocirender`.** The distribution API needed for public and simple private images is a few requests; `oci-client` would bring `tokio`, `reqwest` and the banned `aws-lc-sys` (or a hand-installed provider), and `ocirender` merges layers itself with C compression libraries and a licence `deny.toml` does not allow. `ureq` runs on the `ring` provider the gate uses, `tar` parses, `flate2` and `ruzstd` decompress, `ring` hashes.
- **No ownership override in M5.** The guest's virtio-fs mount enforces permissions from the attributes AuditFs returns, so presenting an image's root ownership would stop the host-uid session from writing what it owns today. Ownership stays as it is (everything the session's, setuid bits kept), and the image's skipped device nodes are listed in `image.json`. Presenting ownership needs root sessions, which is its own decision.
- **Exec denial at ring 0, by path, on the shares.** The sensor has no channel to receive policy from the host, and an LSM deny list it held would be ring 1's. An exec-open on a share is refused by AuditFs; a program copied to the guest's tmpfs is out of reach, and the docs say so.
- **OTLP as JSON, written by hand.** OTLP/HTTP accepts JSON; the trace is a few hundred spans at most per session, so `serde_json` and the OTLP JSON mapping are enough, with no `prost`, generated code or SDK.
- **One seccomp allowlist for the process.** Per-thread filters (Firecracker's) need a syscall inventory per thread role and a filter installed by each thread; one process-wide filter with `TSYNC`, measured over the gated suites, gives most of the containment for a fraction of the risk, and per-thread filters can follow.

Made after the plan's Codex review, 2026-10-14:

- **Policy views, not a shared policy type.** `boxcar-policy` builds on the line policy, so the net stack cannot read a type of `boxcar-policy`'s without a dependency cycle. It compiles into a `boxcar_net::Policy` and a `boxcar_fs::PathRules`, the views those crates read.
- **Paths at ring 0 are the names the share knows.** FUSE hands `open` an inode, not the name the guest used, and the guest resolves symlinks itself. A rule is checked against every name `PathMap` holds for the file, and `[exec] deny` denies program files, not the names they run by (a BusyBox applet is BusyBox).
- **`agent-isolate` lets a session write its own root.** The root share is a per-session copy, so writes outside `/workspace` cannot reach the cache or another session; a package install needs them. `agent-isolate-strict` keeps writes to `/workspace` and `/tmp`.
- **Exceptions apart from the permanent policy**, with ids, so a whole-policy update can neither keep nor revive one, and overlapping grants expire on their own.
- **Landlock before the first thread; `clone3` answered `ENOSYS`.** Landlock reaches only the applying thread and its later children on the test box's kernel, and seccomp cannot read `clone3`'s flags.
- **Bounded decompression**: 16 GiB expanded and 1,000,000 entries per image, counted while streaming.
- **A seccomp kill is a crash.** Task 7 settles how verify reports a crash's torn tail apart from a broken chain, instead of claiming the log stays verifiable.
- **Our own tar framing.** `tar` buffers extension records whole before yielding an entry, and its raw entries ignore a PAX `size` when framing. Task 2 frames the stream itself: headers dispatched by kind (PAX `x` through `tar`'s PAX parser, GNU `L`/`K` as raw names, PAX `g` refused when it overrides an entry), each extension record capped at 64 KiB, overrides carried to the next entry, checksums checked. The 16 GiB budget counts the whole decompressed stream. Sparse files (GNU `S`, `GNU.sparse.*`) are refused in M5 rather than reconstructed.
- **Boot paths made on the host.** Init creates mount points and `/etc/resolv.conf` on the root share at boot; the host makes them in the session copy first, so `agent-isolate-strict` refusing writes outside `/workspace` and `/tmp` does not stop the boot.

Made by Task 2 (`docs/plans/oci-image-cache.md`), 2026-10-16:

- **`RESOLVE_IN_ROOT`, not `RESOLVE_BENEATH`, for unpacking.** `RESOLVE_BENEATH` fails on an absolute symlink in a parent component, and images are full of them (`/etc/alternatives/x -> /usr/bin/y`). `RESOLVE_IN_ROOT` resolves them against the tree's root, as a chroot would, and still confines every resolution to the tree.
- **Whiteouts in a first pass over each layer**, applied as the pass streams them, then the layer's entries in a second: the result does not depend on the order of entries relative to whiteouts, and the pass holds one entry at a time. Among themselves, whiteouts apply in archive order against the tree as it stands, as Docker's applier does.
- **A body deadline from the size, not a stall timeout.** ureq 3 times out a whole body, not one read; the deadline is 30 s plus the size at 64 KiB/s.
- **Only the three final names are ever read.** Everything half-built or half-deleted has a `.`-name with a pid and a counter, which no tag, digest or repository component can have; a sweep removes those of dead pids. Tags live under `_tags`, a component no repository path can have.
- **`syncfs` once for a tree**, then `image.json`, the image directory, the rename and its parent; blobs and refs get `fsync` and their directory's. Refs are unlinked and their directories synced before an image is renamed away.
- **Blobs are kept and shared across images**, each tree unpacked per image; `prune` reclaims what nothing names.
- **A multi-frame zstd adapter of our own** over ruzstd, which decodes one frame and only stores its checksum.
- **`--cache-dir`**, so tests and the test box point the cache anywhere.
- **The test registry is a crate**, `boxcar-testreg`: `boxcar` is a binary, and a test-only crate is the one place its unit tests and the gated suites can both reach.
- Follow-up #35 (2026-10-21): the credential helper the Docker config names for a registry is run (`docker-credential-<name> get`, as Docker runs it), once, at the first challenge, before the Landlock domain and the seccomp filter; its answer is used as `auths` credentials are and never repeated. Identity tokens stay out.

Made by Task 3 (`docs/plans/run-from-image.md`), 2026-10-17:

- **The cache stores readable modes and `image.json` the true ones** (Task 2 amended): an owner cannot read their own `0o000` file, and a session's copy must read every entry without touching the cache; the copy gives the session the image's modes.
- **Index digests are lookup mappings** (Task 2 amended): a reference by an index's digest is found offline through `_indexes` entries beside `_tags`, which go with their image; only tags keep an image from `prune`.
- **`--image` needs the vsock session**: the console session carries only the command, so an image's environment and working directory would be silently lost.
- **The environment is merged to one value per name**, boxcar's defaults, then the image's, then `--env`, the last winning: init keeps duplicates and takes the first `PATH`.
- **The working directory is made where the guest will see it**: the guest's view is the copy with init's mounts applied where `mount(2)` puts them, at the places the image's `/workspace`, `/run`, `/dev`, `/proc` and `/sys` lead once their links are followed; the workspace's host directory is looked up beneath the workspace's place, nothing beneath a kernel filesystem's.
- **Boot paths before modes**: the mount points, the working directory, `/etc/resolv.conf` and the trust store are made in the copy while every directory is still 0o700; modes come last, deepest first.
- **The copy stays with the session as `rootfs`**, like the default workspace; reclaiming sessions is one decision for both. Times are not copied.
- **Loopback registries are plain HTTP** (Docker's insecure-by-default rule for `localhost` and `127.0.0.0/8`), HTTPS when they decline it; redirects are followed by hand so a plain-HTTP redirect anywhere else is still refused.
- **A given command replaces `Entrypoint` and `Cmd` both**; the image's defaults are bounded at 32 KiB.
- **Whiteouts within a layer apply in archive order**, as Docker's applier does (pinned by Task 2's review, recorded here with Task 3).

Made by Task 4 (`docs/plans/policy-files.md`), 2026-10-19:

- **Denies before allows in a policy file.** Its lists have no order between them, so a deny of a target wins over an allow of it, as `--deny` before `--allow` and `policy.update` already order them; the flags add after the file's rules, as they add after a line file's.
- **A target in a list is one word.** `Policy::from_lists` and `Policy::add` parse each target as itself, where `policy.update` used to make it a line in which a space or a `#` cut it short (`"a.test # x"` was taken as `allow a.test`); the flags and `boxcar policy allow|deny` check rules the same way.
- **The DNS rate is the session's**, in `NetConfig`, never in the rules `policy.update` replaces, so no client can lift it; every answered message counts, malformed ones included, before the policy is read.
- **A profile's name is the profile**; anything else given to `--policy` is a path. `--policy` does not need the network.
- **The Debian mirrors on 80 as well as 443** in the profiles: apt's default sources are plain HTTP (signed), and 443 alone would fail `apt-get update`.
- **Absolute globs only, 1024 entries per list, 1 MiB of text** (read no further than one byte past it); a `--policy-file` line policy keeps having no limit and is read whole.
- **`policy.loaded` for every session**, right after `vmm.start`: `flags` names the line policy, its `--policy-file` and the file's hash when there is one.
- **The network half in force first.** Until Task 5 enforces `[fs]`, `[exec]`, `[spans]` and `[record]`, `boxcar run` names on stderr what a policy sets of them that would restrict (`agent-isolate` sets nothing of the kind; `agent-isolate-strict` its `writable` and `[exec] deny`).

Made by Task 5 (`docs/plans/policy-enforcement.md`), 2026-10-19:

- **Denied is held by identity as well as by name.** A boot scan of all the session's shares, as one set, finds the denied entries, the directories holding them and the refused programs. A create, unlink, rmdir and rename reads what its name is now. So no hard link, case-insensitive host or renamed parent reaches a denied file. A directory the scan cannot read, or more than 4,000,000 entries, fails the session before it boots.
- **The node-id gate.** While rules are in force, a request on a node id the path map does not hold is refused: the guest kernel is not trusted to send only the ids it was given.
- **A glob covers what lies beneath what it names, for `denied` and `writable` alike**, so moving a directory out to a writable place and back launders nothing. A denied glob's literal prefix is never renamed.
- **`[exec] deny` refuses every open of the file, and its renames and links**, so the loader route, a copy and a hard link do not run it either. The strict profile also names `nc.openbsd`, `nc.traditional` and `netcat`, which Debian's `nc` resolves to.
- **`readdirplus` lists a denied entry without its inode or attributes**, and records nothing. `opendir` passes on only a directory read's flags, with or without rules.
- **`link` needs its source writable by every name**: a link changes the inode's link count.
- **The default `writable` is `/workspace/**` and `/tmp/**`**, a change to section 3 the owner approved on the pull request. Init mounts no tmpfs on `/tmp`, so `/tmp` is the root share's, and without `/tmp/**` a policy file with only `[egress]` would leave it read-only, which breaks `mktemp`, compilers and package builds. A tmpfs on `/tmp` was refused instead: what is written there would be neither recorded nor policed. The rest of the root share stays read-only unless the file says.
- **An egress exception is an allow after the permanent rules**, so a permanent deny of its target still wins. **An exception comes alone in its `policy.update`**, and the 65th is `busy`.
- **Exceptions expire by `CLOCK_BOOTTIME`**, recorded as realtime `expires_ns`. `policy.changed{by_pid: 0}` marks an expiry, and every policy record is made under the policy's lock, in version order.
- **`keep_tool_args = false` drops the summary as well as the arguments**, and keeps `args_b3`.

Made by Task 7 (`docs/plans/vmm-hardening.md`), 2026-10-20:

- **The allowlist is measured, then completed from the code.** bpftrace on the test box (not `strace -f -c`, which slows the timing-sensitive tests) counted every syscall of every `boxcar` process over `test-kvm m5`, by thread and by argument, from each process's first `KVM_RUN`. What the guest can reach that the suites never did (every FUSE operation the passthrough serves, every socket call of a flow, a device reset) comes from the source: a call off the list is a guest-triggered kill. The list is glibc's on x86_64; other targets refuse `enforce` and `log`.
- **The filter goes in before `vmm.start` is recorded**, in `Vmm::new` once the VM is built, so `vmm.start.hardening` states what is in force. `clone3` is answered `ENOSYS` by a second filter, installed first; `tgkill` and `socketpair` are filtered too.
- **Landlock confines every thread or the run does not start.** On ABI 8 and later (the test box runs Linux 7.0) `LANDLOCK_RESTRICT_SELF_TSYNC` covers every thread; without it `run` waits up to 30 s for threads from before (ureq's resolvers) to end, then refuses. ABI 1 counts as no Landlock: without `REFER` it refuses renames across directories. TCP binds and both scopes are handled; `EXECUTE` is granted nowhere.
- **`run` makes the session's and the state directories before the domain**, and removes them, when empty, on every way out.
- **`--landlock enforce|off`, `BOXCAR_SECCOMP` and `BOXCAR_LANDLOCK`.** The record admits `"off"`, a missed path needs a way out without a new build, and the variables let a whole suite run under `log`. `xtask test-kvm` refuses `off`.
- **The `boot_*` tests run confined, each in a child of its test binary**, since a process-wide filter would bind libtest and every later test.
- **A log cut mid-write is `incomplete`, cause unknown, exit code 4.** Verify cannot tell a crash from a deliberate cut; what a cut tail can hide is bounded by the index, as for a cut at a record boundary. The writer's rollback cuts the index before the segment, so a kill halfway leaves a state a crash can produce.
- **Guest memory is `MADV_DONTDUMP`**, so a kill's core holds none of it.
